## What to build

从手动 m3u8 或扩展媒体入口选择清晰度，下载已有点播分片并通过 Native Go 媒体处理生成成品，在共享窗口完成展示和失败恢复。

## Acceptance criteria

- [ ] 遵循已接受 ADR-0001：HLS Engine 管清单、分片、加密、下载及信息组织，统一 Media Processor 承担解析、轨道合并和输出；具体库只在后端内使用。
- [ ] 默认 Native Go Backend；不依赖或默认打包完整 FFmpeg runtime，不重新编码；保留后端替换边界而不在首期实现 FFmpeg 安装系统。
- [ ] 使用实际样本评估 Go 媒体库，覆盖常见 TS/fMP4、H.264/H.265 + AAC 目标组合，形成准确的支持矩阵。
- [ ] 支持已有 HLS 点播、主清单、初始化片段、媒体分片和标准 AES-128 密钥/IV处理；不进行直播录制或 DRM 处理。
- [ ] 多清晰度在进入信息对话框前选择，进入后固定；悬浮条、资源列表和手动 m3u8 顺序一致，提前下载使用已选版本。
- [ ] 对话框展示已选清晰度和可获得的时长/大小，未知信息明确显示；未确认且未启用提前下载时不下载媒体分片。
- [ ] 处理关联独立音视频轨和时间戳，正确组装、demux、mux、无损 remux 及 MP4 输出；不支持结构明确说明。
- [ ] 分片下载结束立即释放下载名额，共享窗口显示处理状态；成品生成后再提供打开操作。
- [ ] 处理失败保留分片与原因并支持仅重试处理；成功清理临时分片；暂停/恢复与持久化遵守任务规则。
- [ ] 用独立解析或播放验证成品轨道、时间戳、时长和内容；覆盖加密、独立轨道、失败重试、提前下载与不支持样本。
- [ ] 任务内部按 TS 基础闭环、fMP4/codec、加密/独立轨道、入口联动与恢复分步验收，不将单个样本成功等同全部兼容。
