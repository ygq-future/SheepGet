## What to build

从主界面手动添加普通 HTTP/HTTPS 链接，确认后下载并管理任务；完成暂停、继续、重试、排队和恢复，交付可演示的下载核心。文件信息先提供基础确认入口，完整交互由后续任务补齐。

## Acceptance criteria

- [ ] 提供 Windows、macOS、Linux 的基础应用运行路径，记录实际验证的平台与必要技术选型；Go 后端拥有任务状态。
- [ ] 主列表采用 Modern refined desktop utility UI 的高信息密度布局和流畅状态过渡；显示进度、状态及可用操作。
- [ ] 普通文件从输入链接到生成文件完整可用；手动确认过的零进度失败任务仍保留错误和重试入口。
- [ ] 支持暂停、继续、断点续传和失败重试；重启保留记录，全部等待用户手动继续。
- [ ] 默认最多 3 个下载任务，剩余按添加顺序排队；暂停或传输结束释放名额并自动补位。暴露后续设置页所需配置能力。
- [ ] HTTP 采用固定并发上限与动态分块；全局默认和单任务覆盖具备后端能力，不把下载通道数承诺为物理线程数。
- [ ] 验证 Range 响应及文件版本一致性，安全处理服务器忽略 Range、资源变化和不可续传情况，保证输出字节正确。
- [ ] 有空闲通道且无普通待领取块时才协助明显拖尾区块；持续比较近期速度，只拆剩余区间，不超过上限，并有最小块大小、冷却和次数限制。
- [ ] 通过可控服务验证正常下载、暂停恢复、局部慢块与整体限速；阈值由可复现测试确定，1 MB/10 秒不是硬编码需求。
