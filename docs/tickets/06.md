## What to build

在 Chrome 和 Edge 手动加载配套扩展，可靠接管普通下载，并通过资源列表及媒体悬浮条将通用媒体交给桌面端。

## Acceptance criteria

- [ ] 提供随软件附带的可侧载扩展与安装指引，用户开启开发者模式加载；验证稳定标识和更新后的重新加载流程。
- [ ] 普通下载按配置后缀接管；站点排除按发起页面域名及子域名，而非只看 CDN 文件域名；主动下载入口仍可用。
- [ ] 按住自定义快捷键临时暂停或强制接管，松开恢复；强制忽略类型/站点排除，暂停交给浏览器；实际按键捕获边界经验证。
- [ ] 桌面端确认接收后才结束浏览器下载；未运行尝试唤起，不可达时浏览器可继续并提示，验证断连与候选资源取消边界。
- [ ] 传递必要 URL、Cookie、Referer 和 Header 等上下文，避免把请求凭据暴露在普通日志；验证受上下文约束的通用资源。
- [ ] 发现通用媒体直链和 HLS 清单，扩展资源列表可见；本任务完成直链下载，HLS 完整处理由后续任务完成。
- [ ] 可关联播放器的悬浮条贴近右上角，随移动/滚动变化；多播放器独立，视口外隐藏，滚回恢复。
- [ ] 取消信息对话框后悬浮条仍可用；手动关闭仅影响当前播放器直到刷新/重开；无法关联的资源只进入扩展资源列表。
- [ ] 真实 Chrome/Edge 和三平台交接验证优先，不做特定复杂站点解析；技术限制若影响承诺行为，记录证据并说明取舍。

## 实施分期与进度看板（Implementation Roadmap）

为防止上下文遗忘或因实现跨度过大导致逻辑错乱，Ticket 06 严格按照以下 5 个递进阶段推进：

### Phase 1：桌面端服务端点与扩展工程基座
> **目标**：打通跨进程 Loopback 通道，搭建 WXT 扩展脚手架，实现质量门禁全面纳管。

- [ ] **1.1 桌面端 Local Loopback Server**
  - 在 Go 后端（`internal/server/`）实现轻量 HTTP/WebSocket 服务，启动时监听 `127.0.0.1` 动态空闲端口并生成随机 `sessionToken`；
  - 实现端点：`POST /api/v1/handover`、`GET /api/v1/config/takeover`、`GET /api/v1/ping`；
  - 会话元数据写入本地运行时目录（便携模式同级 `./data`，安装模式 `%APPDATA%/sheep-get` 等），供扩展与 Host 发现。
- [ ] **1.2 敏感凭据类型级默认安全防护**
  - 落地 `RequestCredentials` 类型，实现 `MarshalJSON` 与 `Stringer` 脱敏，敏感 Header 仅在组装 `http.Request` 时输出（ADR-0005 决策 5）。
- [ ] **1.3 扩展工程脚手架（WXT + TypeScript + React）**
  - 根目录下创建 `extension/` 独立工程，配置 `wxt.config.ts`；
  - 声明固定公钥派生 `key`，固定 32 位扩展 ID；声明 MV3 核心权限（`downloads`, `webRequest`, `storage`, `tabs`, `scripting`, `<all_urls>`）。
- [ ] **1.4 质量门禁接入**
  - 在 `scripts/quality-gate.mjs` 中新增扩展类型检查（`wxt prepare && tsc --noEmit`）与生产构建（`wxt build`），确保 `bun run quality` 全绿。

---

### Phase 2：配置同步、快捷键与普通下载接管闭环
> **目标**：达成验收项第 2、3、4 条，跑通浏览器原生下载拦截、同步阻塞暂缓与状态回退。

- [ ] **2.1 Service Worker 休眠防坑与配置同步**
  - Background Service Worker 初始化或唤醒时，优先从 `chrome.storage.local` 读取规则；
  - 异步发起轻量版本比对，拉取最新 `TakeoverConfig` 并持久化；
  - 桌面端配置修改时通过 WebSocket 实时推送广播。
- [ ] **2.2 按住快捷键监听（参考 IDM 模式）**
  - Content Script 捕获阶段监听 `window` 的 `keydown` / `keyup`（过滤 `!e.repeat`），向 Background 派发掩码（`Shift/Ctrl/Alt/Ins/Del`）；
  - 监听 `blur` 与 Tab 切换，自动将按键掩码置零防卡死；
  - 确认浏览器特权页面（`chrome://*`）的不可注入边界，自动降级为常规接管。
- [ ] **2.3 普通下载拦截与同步阻塞时序**
  - 监听 `chrome.downloads.onDeterminingFilename` / `onCreated`，根据后缀命中、站点排除、快捷键掩码进行接管判定；
  - 命中接管时调用 `chrome.downloads.pause(downloadId)` 原位挂起原连接；
  - 发送 `HandoverRequest`；收到桌面端入队 ACK 后调用 `chrome.downloads.cancel()` 并擦除痕迹；
  - 超时（2.5 秒）或不可达/显式拒绝时调用 `chrome.downloads.resume()` 恢复浏览器原生下载，并给用户轻量 Toast 提示。

---

### Phase 3：网络通用资源嗅探与扩展资源列表
> **目标**：达成验收项第 6 条前半部分，支持直链及 HLS 清单嗅探并在扩展弹窗展示。

- [ ] **3.1 网络层通用资源嗅探（Background）**
  - 注册 `chrome.webRequest.onHeadersReceived`；
  - 过滤响应头 `Content-Type`（`video/*`、`audio/*`、`application/vnd.apple.mpegurl` 等）与 URL 后缀（`.mp4`, `.mkv`, `.mp3`, `.m3u8` 等）；
  - 将捕获的资源按 `tabId` 归入内存媒体资源池（URL、MIME、大小、页面标题）。
- [ ] **3.2 扩展 Popup 资源列表 UI**
  - 基于 React 实现精致的高信息密度资源列表；
  - 展示当前标签页嗅探到的所有媒体资源，支持一键点击下载；
  - 通用直链点击触发交接移交至桌面端；HLS 清单移交至桌面端记录待处理列表。

---

### Phase 4：DOM 播放器关联与媒体悬浮条
> **目标**：达成验收项第 7、8 条，实现播放器右上角悬浮条及其生命周期。

- [ ] **4.1 播放器 DOM 探测与视口监听**
  - Content Script 通过 `MutationObserver` 探测页面 `<video>` 播放器；
  - 使用 `IntersectionObserver` 监听播放器滚动出入视口（出视口隐藏，滚回恢复）；
  - 监听全屏与窗口变化，精准贴近播放器右上角。
- [ ] **4.2 资源与播放器关联裁决**
  - 将嗅探到的媒体 URL 与当前 `<video>` 的 `src` 或播放上下文尝试关联；
  - 关联成功者渲染悬浮条；无法关联者自动收敛至 Phase 3 资源列表。
- [ ] **4.3 悬浮条交互闭环**
  - 点击发起下载移交并唤起文件信息窗口；
  - 取消文件信息窗口后悬浮条仍保持可用可点击；
  - 点击悬浮条关闭按钮（X）仅隐藏当前播放器直到页面刷新，不影响其他播放器。
