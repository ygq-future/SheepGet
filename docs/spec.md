# SheepGet 第一版产品规格

状态：已确认。产品决策与测试边界均已确认；本规格面向多阶段实施，未将技术验证项视为已完成。

跟踪位置：[GitHub Issue #1](https://github.com/ygq-future/SheepGet/issues/1)。

## Problem Statement

用户需要一款跨平台、轻量、以下载任务为中心的桌面下载管理器，可靠接管浏览器中的普通文件及常见媒体下载。现有体验中，任务窗口过多、取消操作后媒体入口消失、确认前隐式下载及难以控制的保存行为影响日常使用。

SheepGet 需要在 Windows、macOS 和 Linux 提供一致的核心行为：浏览器集成、可控的开始下载时机、分类保存、多连接与续传、集中进度展示，以及常见点播媒体的正确合并。产品范围聚焦通用下载场景，保持安装与运行负担可控。

## Solution

提供基于 Wails v3 Beta（`v3.0.0-beta.20`）+ Go (1.27) + React 19 + TypeScript 的桌面应用及配套 Chrome / Edge 扩展。界面采用 Modern refined desktop utility UI，参考 Linear + Raycast 的克制、精致和高信息密度，组件状态变化具有流畅过渡。

架构采用**原生多窗口模型**（遵循 ADR-0002）与**配置中心单一事实来源**（遵循 ADR-0003）。主要窗口包括主窗口（全量任务管理与设置中心）、文件信息窗口（独立桌面辅助窗口，在主窗口驻留托盘时可独立唤起与关闭，支持多任务队列管理与即时响应）和共享下载进度窗口（多任务实时分块与进度、置顶完成信息）。前端采用 SPA 模式按窗口类型路由挂载对应精简根视图。

用户通过浏览器接管、媒体悬浮条、扩展资源列表、剪贴板监视或手动添加链接进入下载流程。媒体先选择清晰度，再打开独立文件信息窗口；默认确认后下载，可按配置中心启用窗口打开期间提前下载。所有任务集中管理，一个共享下载进度窗口承载多个任务，完成后原区域变为完成信息。

Go 后端拥有任务状态、调度与配置中心。HTTP 下载采用可配置的并发上限、动态分块和有条件的慢区块再拆分。HLS 下载与媒体处理分层，默认 Native Go Backend（ADR-0001）负责常见媒体组合的无损封装；支持范围外的媒体明确提示不支持。
## User Stories

1. 作为桌面用户，我希望在 Windows、macOS 和 Linux 使用 SheepGet，以便在不同系统保持相同的下载流程。
2. 作为用户，我希望主界面围绕下载列表提供高信息密度的清晰布局，以便快速了解任务并操作。
3. 作为用户，我希望各组件具有流畅的动画过渡，以便理解状态与位置变化。
4. 作为用户，我希望关闭主窗口后应用驻留托盘，以便下载和已启用的监听继续运行。
5. 作为用户，我希望配置开机启动，以便按个人习惯运行应用。
6. 作为 Chrome / Edge 用户，我希望软件附带扩展文件和手动加载指引，以便通过开发者模式安装配套扩展。
7. 作为浏览器用户，我希望符合配置的普通文件下载交给 SheepGet，以便集中管理下载。
8. 作为用户，我希望自动接管文件类型预置常见后缀并可配置，以便控制接管范围。
9. 作为用户，我希望排除某个页面站点及其子域名，以便这些页面的下载留在浏览器中。
10. 作为用户，我希望站点排除不妨碍主动下载，以便仍可使用悬浮条或手动添加链接。
11. 作为用户，我希望按住可自定义的快捷键临时暂停或强制接管，以便只改变当前下载行为。
12. 作为用户，我希望松开快捷键就恢复原有规则，以便不改变全局设置。
13. 作为用户，我希望交接失败时浏览器仍能下载并提示原因，以便任务不因 SheepGet 不可用而丢失。
14. 作为用户，我希望应用未运行时扩展尝试唤起它，以便继续接管流程。
15. 作为用户，我希望配置剪贴板监视开关，以便自行决定是否自动发现复制的文件链接。
16. 作为用户，我希望剪贴板监视按已配置的接管类型匹配 URL 路径后缀，以便普通网页链接不频繁触发对话框。
17. 作为用户，我希望手动添加无明确后缀的链接，以便下载剪贴板规则未覆盖的文件。
18. 作为媒体下载用户，我希望扩展发现通用视频、音频和 HLS 资源并携带必要请求信息，以便桌面端取得资源。
19. 作为用户，我希望每个可关联播放器拥有小巧且准确定位的悬浮条，以便从对应媒体发起下载。
20. 作为用户，我希望悬浮条随播放器移动和滚动显示，以便入口始终对应当前播放器。
21. 作为用户，我希望取消文件信息窗口后仍能再次点击悬浮条，以便重新发起下载。
22. 作为用户，我希望关闭悬浮条只影响当前播放器且刷新后恢复，以便控制页面干扰。
23. 作为用户，我希望无法关联播放器的媒体出现在扩展资源列表中，以便仍可选择下载。
24. 作为用户，我希望多清晰度资源在进入文件信息窗口前选择清晰度，以便下载版本从一开始就明确。
25. 作为用户，我希望手动添加 m3u8 也遵守先选清晰度的顺序，以便各入口行为一致。
26. 作为用户，我希望文件信息窗口作为独立辅助窗口展示名称、类型、大小、来源和保存位置，以便确认本次下载。
27. 作为用户，我希望主窗口驻留托盘时，外部触发下载仅弹出独立文件信息窗口，以便不干扰当前屏幕焦点和主界面。
28. 作为用户，我希望连续多次点击新建任务时能同时独立弹出文件信息窗口，以便获得明确即时的视觉反馈与独立操作体验。
29. 作为用户，我希望 HLS 展示已选清晰度以及可获得的时长和大小，以便理解所选资源。
30. 作为用户，我希望信息不完整时显示未知且仍可下载，以便信息探测失败不阻断可用资源。
31. 作为用户，我希望在文件信息窗口修改名称和保存位置，以便控制最终文件。
32. 作为用户，我希望默认确认前只获取必要信息，以便自己决定正式传输的时机。
33. 作为用户，我希望可在配置中心开启显示文件信息时立即下载，以便编辑保存信息期间已在后台传输。
34. 作为用户，我希望提前下载完成后确认即可看到完成信息，以便直接操作成品。
35. 作为用户，我希望取消尚未确认且未实际下载的候选资源不留下任务，以便列表保持清楚。
36. 作为用户，我希望提前下载后取消窗口会停止传输并保留暂停任务，以便之后继续。
37. 作为用户，我希望手动确认的任务即使零进度失败也保留，以便查看原因并重试。
38. 作为用户，我希望预置文件、视频、音频、图片、压缩包和软件分类及可配置目录，以便自动归档。
39. 作为用户，我希望创建按后缀匹配的自定义分类，以便使用自己的文件组织方式。
40. 作为用户，我希望自定义规则优先且内置规则保持完整，以便重叠后缀优先进入自定义分类。
41. 作为用户，我希望新增自定义分类置顶并支持拖动排序，以便明确匹配优先级。
42. 作为用户，我希望手动选择的保存位置优先于分类，以便控制单次下载目的地。
43. 作为用户，我希望分类规则与接管规则独立，以便改目录不会改变浏览器接管行为。
44. 作为用户，我希望设置临时文件夹，以便控制下载过程中的磁盘占用位置。
45. 作为用户，我希望便携版将所有配置与数据保存在程序同级目录，以便免安装即拷即用。
46. 作为用户，我希望在配置中心切换浅色/深色/跟随系统主题及选择个性化强调色，以便获得一致的视觉体验。
47. 作为用户，我希望在配置中心设置重复链接全局策略（询问、跳过并显示完成信息、继续下载并覆盖、序号副本），以便按个人习惯处理重复资源。
48. 作为用户，我希望选择“跳过并显示完成信息”时，直接唤起并定位到共享进度窗口的完成区域，不重复弹出文件信息窗口。
49. 作为用户，我希望同名文件冲突单独处理，以便选择覆盖或自动加序号。
50. 作为用户，我希望可使用服务器提供的文件时间，以便保留可获得的原始时间信息；具体时间字段语义需验证。
51. 作为用户，我希望全局设置连接数且可为单个任务覆盖，以便按资源调整并发上限。
52. 作为用户，我希望空闲通道继续领取区块，以便保持分块下载效率。
53. 作为用户，我希望明显拖尾的慢区块得到有限拆分协助，以便减少等待，同时避免整体网速慢时反复拆分。
54. 作为用户，我希望暂停、继续、断点续传和失败重试，以便应对网络中断。
55. 作为用户，我希望链接过期后能更新链接并校验文件一致性，以便安全利用已有数据。
56. 作为用户，我希望配置同时下载任务数，默认 3 个且其余按添加顺序排队，以便控制整体负载。
57. 作为用户，我希望任务下载结束或暂停后队列自动补位，以便充分使用下载名额。
58. 作为用户，我希望重启软件后等待手动继续未完成任务，以便自行控制恢复时机。
59. 作为用户，我希望选择直连、系统代理或自定义代理，以便适应网络环境。
60. 作为用户，我希望代理设置变化只用于新任务及暂停后继续的任务，以便当前下载不被打断。
61. 作为用户，我希望多个任务共享一个独立下载进度窗口，以便避免窗口堆积。
62. 作为用户，我希望看到各任务实时下载区块和进度，下载中任务按进度降序排列，以便识别接近完成的任务。
63. 作为用户，我希望进度窗口限制高度并在内部滚动，以便任务多时仍可使用。
64. 作为用户，我希望完成信息固定顶部并可打开文件或文件夹，以便快速使用下载结果。
65. 作为用户，我希望手动移除完成信息，或配置打开文件/文件夹后自动移除，以便整理进度窗口。
66. 作为用户，我希望分别配置显示下载进度窗口和保留完成信息，以便控制提示方式。
67. 作为用户，我希望下载现有 HLS 点播资源，包括标准 AES-128、TS/fMP4 及常见 H.264/H.265 + AAC，以便保存常见网页媒体。
68. 作为用户，我希望分片正确合并和无损重新封装，以便获得可直接使用的成品。
69. 作为用户，我希望合并失败后保留分片并仅重试处理，以便避免重复下载。
70. 作为用户，我希望不支持的媒体得到明确说明，以便理解失败原因。
71. 作为用户，我希望默认安装即可处理所支持的媒体且保持轻量，以便无需自行安装必需的 FFmpeg 工具链。
## Implementation Decisions

### 架构与原生多窗口模型

- 遵循 ADR-0002：采用 Wails v3 Beta（`v3.0.0-beta.20`）程序化架构支撑原生多窗口与跨平台系统托盘（`app.SystemTray`），各窗口由 Go 后端统一调度：
  - **主窗口（Main Window）**：管理任务总览、主列表操作及设置中心内嵌视图；关闭时隐藏驻留托盘，不退出应用进程。
  - **文件信息窗口（File Info Window）**：独立小巧的原生桌面辅助窗口（SPA 路由 `/?window=fileinfo`），在主窗口最小化至托盘时可独立唤起与关闭，绝不触发主窗口显示。支持多实例同时并发展示，多次触发时即时弹出新窗口响应。
  - **共享下载进度窗口（Shared Progress Window）**：独立共享窗口（SPA 路由 `/?window=progress`），承载多任务实时分块、下载进度及置顶完成信息。
- 前端采用 SPA 统一单页多路由架构，各原生窗口加载时挂载专属精简根视图，共享 Tailwind CSS 变量、全局设计系统及状态总线。
- Task Orchestration 在 Go 后端拥有任务生命周期、队列、状态持久化与调度规则的单一事实来源。前端负责展示与提交操作，不自建业务状态机。
- 遵循 ADR-0001：Native Go Backend 为统一媒体处理层默认实现，具体媒体库封装于内部；首期保留未来可选 FFmpeg 后端的无缝接入边界。

### 配置中心与双轨数据存储

- 遵循 ADR-0003：配置中心（Settings Center）作为系统所有全局规则与外观偏好的单一事实来源。
- **双轨存储判定**：
  - **便携模式**：程序目录存在 `data/` 文件夹或 `portable` 标记文件时生效，全量配置（`config.json`）、任务数据库和临时文件全部存放在程序同级 `./data`，实现免安装即拷即用。
  - **安装模式**：按平台规范存放于标准系统用户数据目录（Windows `%APPDATA%\SheepGet`、macOS `~/Library/Application Support/SheepGet`、Linux `$XDG_DATA_HOME/sheepget`）。
- **配置项范围**：
  - `appearance`：主题模式（`system` | `light` | `dark`）、个性化强调色（`accentColor`）。
  - `download`：重复链接全局策略（`duplicateUrlPolicy`）、提前下载默认开关（`preDownload`）、最大同时下载数（`maxConcurrentDownloads`，默认 3）、单任务默认连接数（`defaultConnectionsPerTask`，默认 4）、默认下载目录与临时目录。
- **设置交互**：设置面板作为主窗口内嵌的优雅视图（由侧边栏/标题栏设置图标或托盘菜单“偏好设置”触发），修改立即通过后端事件总线热同步至所有活跃窗口。

### 入口、文件信息窗口与重复策略

- 自动接管由独立的后缀配置和页面站点排除规则决定。站点按发起页面域名及子域名匹配；主动操作可使用下载入口。
- 临时暂停/强制接管快捷键按住生效，松开恢复。强制接管跳过后缀及站点排除规则。
- 剪贴板仅自动匹配 HTTP/HTTPS URL 的路径后缀，忽略查询参数。无后缀链接使用手动添加。
- 悬浮条贴近对应播放器右上角，随位置和视口变化；多播放器各自管理入口。无法关联播放器时使用扩展资源列表。
- 多清晰度选择发生在文件信息窗口之前，进入后固定；手动 m3u8 入口同样执行该步骤。
- 默认仅探测必要元信息；未知大小明确显示未知，不妨碍确认下载。
- 提前下载开关由配置中心提供默认值，窗口内可针对单任务覆盖。开启时仍显示窗口并允许编辑名称与目录；确认后成品使用最终保存信息。
- **重复链接策略规则**：
  - 全局配置支持四种行为：`prompt`（询问，默认）、`skip_show_completed`（跳过并显示完成信息）、`continue_overwrite`（继续下载并覆盖）、`numbered_copy`（序号副本）。
  - 配置为 `prompt` 时，弹出文件信息窗口并提供上述后三种选项供用户选择。
  - 配置为 `skip_show_completed`（或用户在询问中选择该项）时，若存在对应已完成任务，系统唤起并聚焦“共享下载进度窗口”，将其滚动定位至置顶的完成区域，同时保持文件信息窗口开启供进一步操作。
  - 配置为 `continue_overwrite` 或 `numbered_copy` 时，唤起文件信息窗口进行保存信息确认，确认后分别执行已有任务续传/覆盖或序号副本创建。
- **同名文件冲突**：以目标保存位置为准，独立于重复链接判断，默认询问，支持覆盖或添加序号；提前下载在同名冲突未决前不落盘写入。

### 任务保留与窗口行为

| 触发条件 | 已确认行为 |
| --- | --- |
| 未确认且未实际下载，取消文件信息窗口 | 不保留任务 |
| 提前下载已开始，取消文件信息窗口 | 停止传输，保留为暂停任务 |
| 提前下载已完成，取消文件信息窗口 | 保留为已完成任务与成品文件，不降级丢弃 |
| 手动确认后零进度失败 | 保留失败任务及原因 |
| 重启软件 | 保留记录，等待手动继续 |
| 分片下载完成 | 释放下载名额，进入媒体处理 |
| 媒体处理失败 | 保留分片和错误，允许仅重试处理 |
| 成品生成成功 | 显示完成信息，清理临时分片 |

- 共享下载进度窗口独立于主界面，确认任务后按显示设置打开；后续任务追加。窗口限高，溢出内部滚动。
- 下载中任务按进度从高到低实时排序；已完成任务固定顶部，不参与该重排。完成区域才显示打开文件/文件夹操作。
- 完成信息可手动关闭；提供打开文件/文件夹后自动移除设置。移除展示不删除主界面记录。
- 关闭保留完成信息时，任务完成后从进度窗口移除；关闭自动显示进度窗口时，完成也不主动弹窗。
- 主窗口关闭固定驻留托盘，继续已有下载与启用的监听，不提供关闭即退出选项。

### 分类与网络配置

- 每任务并发上限采用全局默认，可单独覆盖。动态分块队列让空闲通道领取下一块；小文件、剩余块和服务器能力限制实际并发。
- 验证实际 Range 响应，支持不具备分段能力时的单路处理；续传和新链接必须校验文件一致性，无法确认时提示重新下载。
- 慢区块优化仅在有空闲通道且没有普通待领取块时协助拖尾。比较同任务通道的近期持续表现，并考虑剩余量和预计耗时。
- 只再拆分未完成区间，保留已有数据，不突破并发上限；保证区间写入互斥，处理旧请求终止和资源一致性。
- 最小块大小、冷却和有限拆分次数通过测试确定。整体变慢或缺少可靠样本时保守处理，停滞使用超时重试。1 MB/10 秒是问题示例，不是固定验收阈值。

### 媒体支持范围

- 下载现有点播资源，覆盖常见 HLS 清单、TS/fMP4、标准 AES-128 和 H.264/H.265 + AAC 目标组合。
- 默认 Go 原生或成熟 Go 库完成组装和无损封装；具体库与兼容矩阵通过样本验证。
- 支持范围外的 codec、封装或复杂结构明确报不支持。处理错误与下载错误区分；重试处理应复用保存的分片。
- 媒体处理与下载名额独立；合并并发数尚未选定，不将讨论中的单路建议视为既定要求。

## Testing Decisions

### 最高测试切缝（Testing Seams）

1. **切缝 1：配置中心与双轨存储切缝（`SettingsService` + 物理文件路径）**
   - **验证重点**：便携模式（同级 `portable` 或 `data/`）与平台标准安装目录的真实写入隔离；`config.json` 原子落盘；外观主题/强调色与下载行为（重复策略、提前下载、连接数、默认目录）热更新事件总线广播。
2. **切缝 2：原生窗口控制器与任务调度切缝（Window Controller + Task Manager）**
   - **验证重点**：
     - **独立唤起**：主窗口最小化至系统托盘时，外部下载请求仅唤起独立文件信息窗口，主窗口保持隐藏；
     - **独立并发展示**：连续触发新建下载时能同时展示多个独立文件信息窗口，每个窗口具备独立状态与即时操作反馈；
     - **重复策略调度分支**：配置或用户选择“跳过并显示完成信息”时，直接聚焦并展示共享下载进度窗口完成区域，不弹文件信息窗口；选择“序号副本”或“继续覆盖”则弹出文件信息窗口确认。
3. **切缝 3：传输与任务编排切缝（HTTP/HLS Transfer Engine + Task Orchestration）**
   - **验证重点**：以公开操作（添加、暂停、继续、更新链接、慢区块协助）驱动，在可控 Range HTTP/HLS 服务与真实文件系统下验证输出字节逐字节一致性、版本一致性与失败恢复。

### 核心验收场景

| 编号 | 场景与通过标准 |

| A19 | 三平台关闭主窗口后驻留托盘，监听和任务按设置运行；重启后保留记录并等待手动继续。 |

## Out of Scope

- Safari 及其他浏览器扩展；其他桌面应用自身下载的系统级拦截。
- BitTorrent、Magnet、ED2K、FTP、整站离线抓取及特定复杂站点专项解析。
- 直播录制、DRM 破解、Widevine/FairPlay/PlayReady 或浏览器媒体内存提取。
- 任意 codec/封装的全面兼容、重新编码及通用媒体编辑工具能力。
- 第一版必需的 FFmpeg 依赖、默认打包完整 FFmpeg runtime，以及首期实现可选 FFmpeg 后端的安装/更新系统。
- 依据吞吐自动寻找最佳目标并发数的自适应模式；已确认的固定上限内慢区块协助属于首期。
- 应用重启后自动继续未完成任务、关闭主窗口即退出的设置。

## Further Notes

本规格依据项目说明、需求访谈记录、领域术语及已接受的 ADR-0001。以最终确认行为为准；实现技术尚未确定的事项不应在拆票时被静默当成既定选型。

### 实施前需验证或细化

1. 浏览器交接的接收确认时机与用户最终确认不同：应验证候选资源已交接、尚未确认且随后取消的清理行为，及断连后的浏览器恢复能力。
2. 三平台浏览器侧载、稳定扩展标识、更新生效、桌面唤起和按住快捷键的可行边界；Linux 桌面环境及最低系统版本形成兼容矩阵。
3. 元信息探测的请求边界及缺失信息的回退；“使用服务器文件创建时间”的真实字段语义与平台支持，不将修改时间误称创建时间。
4. 文件身份验证策略；无可靠验证信息时的处理不得悄悄混用不同资源。
5. Native Go 媒体库、目标组合及复杂结构的支持矩阵；默认安装包体积通过实际构建测量，不预设未经验证的数字。
6. 时间阈值、区块大小、重试退避、全局默认连接数、媒体处理并发及窗口具体尺寸由技术设计与测试细化。
7. 共享窗口中未知总量、等待、暂停、处理和失败任务的排列应保持可理解；已完成顶部和下载中降序是确定规则。
8. 提前下载已彻底完成后再取消信息对话框，与“取消后保留暂停”规则存在终态边界，需在状态设计时明确，不能把可用成品错误降级或丢弃。
9. 原说明提及限速方向，但未确定首期范围、全局/单任务控制及交互；保留为待归类项，不自行扩成完整限速功能。

这些验证不重开常规需求访谈；只有结果会改变已确认的行为、范围或媒体架构边界时，才向用户说明影响并确认取舍。

规格适合作为母 issue，经技术验证和依赖梳理后拆成可独立验收的实施任务。ready-for-agent 表示无需再做需求分诊，不表示上述验证已通过，也不表示整个产品应在一次实施中完成。
