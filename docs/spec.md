# SheepGet 第一版产品规格

状态：已确认。产品决策与测试边界均已确认；本规格面向多阶段实施，未将技术验证项视为已完成。

跟踪位置：[GitHub Issue #1](https://github.com/ygq-future/SheepGet/issues/1)。

## Problem Statement

用户需要一款跨平台、轻量、以下载任务为中心的桌面下载管理器，可靠接管浏览器中的普通文件及常见媒体下载。现有体验中，任务窗口过多、取消操作后媒体入口消失、确认前隐式下载及难以控制的保存行为影响日常使用。

SheepGet 需要在 Windows、macOS 和 Linux 提供一致的核心行为：浏览器集成、可控的开始下载时机、分类保存、多连接与续传、集中进度展示，以及常见点播媒体的正确合并。产品范围聚焦通用下载场景，保持安装与运行负担可控。

## Solution

提供 Wails + Go + Web 前端的桌面应用方向及 Chrome / Edge 配套扩展。主界面采用 Modern refined desktop utility UI，参考 Linear + Raycast 的克制、精致和高信息密度，以下载列表为核心，组件状态变化具有流畅过渡。

用户通过浏览器接管、媒体悬浮条、扩展资源列表、剪贴板监视或手动添加链接进入下载流程。媒体先选择清晰度，再打开文件信息对话框；默认确认后下载，可启用对话框打开期间提前下载。所有任务集中管理，一个共享下载进度窗口承载多个任务，完成后原区域变为完成信息。

Go 后端拥有任务状态与调度。HTTP 下载采用可配置的并发上限、动态分块和有条件的慢区块再拆分。HLS 下载与媒体处理分层，默认 Native Go Backend 负责常见媒体组合的无损封装；支持范围外的媒体明确提示不支持。

## User Stories

1. 作为桌面用户，我希望在 Windows、macOS 和 Linux 使用 SheepGet，以便在不同系统保持相同的下载流程。
2. 作为用户，我希望主界面围绕下载列表提供高信息密度的清晰布局，以便快速了解任务并操作。
3. 作为用户，我希望各组件具有流畅的动画过渡，以便理解状态与位置变化。
4. 作为用户，我希望关闭主窗口后应用驻留托盘，以便下载和已启用的监听继续运行。
5. 作为用户，我希望配置开机启动，以便按个人习惯运行应用。
6. 作为 Chrome / Edge 用户，我希望软件附带扩展文件和手动加载指引，以便通过开发者模式安装配套扩展。

## Implementation Decisions

### 产品和模块边界

- 桌面端目标为 Windows、macOS、Linux；Wails + Go + Web 前端为当前技术方向。具体版本、前端框架、存储和通信协议尚未选定。
- Task Orchestration 在 Go 后端拥有任务状态、排队、暂停、恢复和重试。前端展示状态与发起操作；HTTP Transfer Engine 与 HLS Engine 分别处理资源传输。
- Browser Integration 承担资源发现、接管规则及交接；系统集成承担托盘、启动和剪贴板能力。扩展不承担大文件传输与复杂媒体处理。
- Media Processor 是统一媒体边界。HLS Engine 负责清单、分片、加密、下载和媒体信息组织；具体 TS/fMP4 解析、音视频轨合并、demux、mux、MP4 输出及无损 remux 由媒体后端负责。
- 遵循 ADR-0001：Native Go Backend 是默认实现，具体媒体库封装在后端内。未来可选 FFmpeg Backend 的接入不应要求重构 HLS Engine 或任务系统；首期仅保留替换边界。
- 普通媒体直链按文件下载；列入直链类型不意味着承诺对该格式进行解析或重新封装。

### 入口与文件信息对话框

- 自动接管由独立的后缀配置和页面站点排除规则决定。站点按发起页面域名及子域名匹配；主动操作可使用下载入口。
- 临时暂停/强制接管快捷键按住生效，松开恢复。强制接管跳过后缀及站点排除规则；可用组合和捕获能力需在目标浏览器验证。
- 剪贴板仅自动匹配 HTTP/HTTPS URL 的路径后缀，忽略查询参数。无后缀链接使用手动添加。
- 交接确认后才能结束浏览器下载。不可用时尝试唤起应用，连接失败保留浏览器下载并提示；握手与恢复机制属于验证项。
- 悬浮条贴近对应播放器右上角，随位置和视口变化；多播放器各自管理入口。手动关闭隐藏至页面刷新或重新打开。无法关联播放器时使用扩展资源列表。
- 多清晰度选择发生在文件信息对话框之前，进入后固定；手动 m3u8 入口同样执行该步骤。
- 默认仅探测必要元信息，HLS 可读取清单但不传输媒体分片；未知大小明确显示未知，不妨碍确认下载。
- 提前下载开关不隐藏文件信息对话框。用户仍可修改名称和目录，最终输出使用确认后的保存信息；正式输出与临时数据的交接需保证文件正确。

### 任务保留与窗口行为

| 触发条件 | 已确认行为 |
| --- | --- |
| 未确认且未实际下载，取消信息对话框 | 不保留任务 |
| 提前下载已开始，取消信息对话框 | 停止传输，保留为暂停任务 |
| 手动确认后零进度失败 | 保留失败任务及原因 |
| 重启软件 | 保留记录，等待手动继续 |
| 分片下载完成 | 释放下载名额，进入媒体处理 |
| 媒体处理失败 | 保留分片和错误，允许仅重试处理 |
| 成品生成成功 | 显示完成信息，清理临时分片 |

- 一个共享下载进度窗口独立于主界面，确认任务后按显示设置打开；后续任务追加。窗口限高，溢出滚动。
- 下载中任务按进度从高到低实时排序；已完成任务固定顶部，不参与该重排。完成区域才显示打开文件/文件夹操作。
- 完成信息可手动关闭；提供打开文件/文件夹后自动移除设置。移除展示不删除主界面记录。
- 关闭保留完成信息时，任务完成后从进度窗口移除；关闭自动显示进度窗口时，完成也不主动弹窗。
- 主窗口关闭固定驻留托盘，继续已有下载与启用的监听，不提供关闭即退出选项。

### 分类、冲突与网络配置

- 自定义分类先于内置分类，按可拖动的列表从上往下首个匹配；新增置顶。规则允许重叠，不从内置分类删除相同后缀。未匹配归入文件，手动目录优先。
- 重复链接先按完整 URL 相同判定，默认询问；继续已有任务直接定位原任务，新下载再检查同名文件。保留原需求中的询问、序号副本、覆盖、已完成展示/未完成继续等策略方向；策略默认以外的具体呈现按流程整理。
- 同名文件冲突以目标保存位置为准，默认询问，支持覆盖或添加序号。
- 代理仅控制 SheepGet 自身联网。正在下载的任务沿用原配置，新任务及暂停后继续使用最新配置；不修改系统/浏览器代理。
- 默认最多 3 个下载任务，可配置；其他任务按添加顺序排队，完成或暂停后补位。提前下载同样受限，可能等待名额。

### HTTP 下载与慢区块调度

- 每任务并发上限采用全局默认，可单独覆盖。动态分块队列让空闲通道领取下一块；小文件、剩余块和服务器能力限制实际并发。
- 验证实际 Range 响应，支持不具备分段能力时的单路处理；续传和新链接必须校验文件一致性，无法确认时提示重新下载。
- 慢区块优化仅在有空闲通道且没有普通待领取块时协助拖尾。比较同任务通道的近期持续表现，并考虑剩余量和预计耗时。
- 只再拆分未完成区间，保留已有数据，不突破并发上限；保证区间写入互斥，处理旧请求终止和资源一致性。
- 最小块大小、冷却和有限拆分次数通过测试确定。整体变慢或缺少可靠样本时保守处理，停滞使用超时重试。1 MB/10 秒是问题示例，不是固定验收阈值。

### 媒体支持范围

- 下载现有点播资源，覆盖常见 HLS 清单、TS/fMP4、标准 AES-128 和 H.264/H.265 + AAC 目标组合。
- 默认 Go 原生或成熟 Go 库完成组装和无损封装；具体库与兼容矩阵通过样本验证。
- 支持范围外的 codec、封装或复杂结构明确报不支持。处理错误与下载错误区分；重试处理应复用保存的分片。
- 媒体处理与下载名额独立；合并并发数尚未选定，不将讨论中的单路建议视为既定要求。

## Testing Decisions

以下测试边界已由用户确认。当前只有文档，无代码、测试框架或既有测试可复用。

### 主要入口：任务公开操作与可观察结果

以添加资源、确认、暂停、继续、更新链接及重试处理等用户级操作驱动完整流程，通过任务可见状态、对外请求和实际输出文件验证行为。使用可控 HTTP/HLS 服务、临时文件区和可控时间制造故障；避免把内部函数调用次数、私有数据结构或所选库类型作为验收目标。

该入口覆盖 Task Orchestration、HTTP/HLS 传输、分类规则、持久化恢复与媒体处理集成，尽量避免为每个内部模块各造一套模拟测试边界。

### 必要的外围验证

- 浏览器/桌面端到端验证：真实 Chrome / Edge 上测试扩展加载、资源发现、交接失败恢复、站点规则、快捷键、悬浮条与桌面窗口。跨三平台验证托盘、剪贴板、启动和文件打开等系统行为。
- Media Processor 契约验证：用固定 TS/fMP4 和音视频轨样本验证默认后端的输出轨道、时间戳、时长与内容完整性；验证不支持输入、失败保留与重试。通过独立解析/播放检查避免只以同一库自读成功判定正确。
- UI 可视交互验证：共享窗口限高、滚动、排序、完成信息及动画；不要求每一内部组件的实现细节测试。

### 核心验收场景

| 编号 | 场景与通过标准 |

## Out of Scope

- Safari 及其他浏览器扩展；其他桌面应用自身下载的系统级拦截。
- BitTorrent、Magnet、ED2K、FTP、整站离线抓取及特定复杂站点专项解析。
- 直播录制、DRM 破解、Widevine/FairPlay/PlayReady 或浏览器媒体内存提取。
- 任意 codec/封装的全面兼容、重新编码及通用媒体编辑工具能力。
- 第一版必需的 FFmpeg 依赖、默认打包完整 FFmpeg runtime，以及首期实现可选 FFmpeg 后端的安装/更新系统。
- 依据吞吐自动寻找最佳目标并发数的自适应模式；已确认的固定上限内慢区块协助属于首期。
- 应用重启后自动继续未完成任务、关闭主窗口即退出的设置。

## Further Notes

本规格依据项目说明、需求访谈记录、领域术语及已接受的 ADR-0001。以最终确认行为为准；实现技术尚未确定的事项不应在拆票时被静默当成既定选型。

### 实施前需验证或细化

1. 浏览器交接的接收确认时机与用户最终确认不同：应验证候选资源已交接、尚未确认且随后取消的清理行为，及断连后的浏览器恢复能力。
2. 三平台浏览器侧载、稳定扩展标识、更新生效、桌面唤起和按住快捷键的可行边界；Linux 桌面环境及最低系统版本形成兼容矩阵。
3. 元信息探测的请求边界及缺失信息的回退；“使用服务器文件创建时间”的真实字段语义与平台支持，不将修改时间误称创建时间。
4. 文件身份验证策略；无可靠验证信息时的处理不得悄悄混用不同资源。
5. Native Go 媒体库、目标组合及复杂结构的支持矩阵；默认安装包体积通过实际构建测量，不预设未经验证的数字。
6. 时间阈值、区块大小、重试退避、全局默认连接数、媒体处理并发及窗口具体尺寸由技术设计与测试细化。
7. 共享窗口中未知总量、等待、暂停、处理和失败任务的排列应保持可理解；已完成顶部和下载中降序是确定规则。
8. 提前下载已彻底完成后再取消信息对话框，与“取消后保留暂停”规则存在终态边界，需在状态设计时明确，不能把可用成品错误降级或丢弃。
9. 原说明提及限速方向，但未确定首期范围、全局/单任务控制及交互；保留为待归类项，不自行扩成完整限速功能。

这些验证不重开常规需求访谈；只有结果会改变已确认的行为、范围或媒体架构边界时，才向用户说明影响并确认取舍。

规格适合作为母 issue，经技术验证和依赖梳理后拆成可独立验收的实施任务。ready-for-agent 表示无需再做需求分诊，不表示上述验证已通过，也不表示整个产品应在一次实施中完成。
