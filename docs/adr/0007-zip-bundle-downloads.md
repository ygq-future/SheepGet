# zip 聚合下载（Zip Bundle）

当第三方工具或 Agent 一次下载同一应用、模型、场景或数据集的多个零散文件时，逐个建任务会在任务列表留下大量小条目，并放大小文件带来的调度与任务库写入开销。本 ADR 规定这类批量下载的契约：一个批次只对应一个任务，成员先登记、后下载，闭合后打包成一个 zip。

## 决策 1：一个批次 = 一个任务

### 候选选项

- **选项 A（每个文件一个隐藏任务 + 聚合视图）**：复用现有下载与续传逻辑，界面只展示汇总项。
- **选项 B（一个任务内嵌成员表）**：批次任务持有成员元数据，成员不建任务。

### 权衡与取舍

选项 A 仍然会把 N 条记录写进 `tasks.json`，并在每个成员上产生进度事件与调度状态；「不显示成员任务」只能靠过滤，存储与调度成本没有消失。选项 B 让批次成为唯一事实来源，任务库、调度与事件都只看到一条记录；成员明细只用于续传与打包。

### 决策结论

采用选项 B。`Task.Bundle` 保存批次事实与成员表；成员没有独立任务 ID，不产生成员级进度事件。事件载荷在广播前剥掉成员明细，只保留文件计数与大小汇总，避免事件体积随成员数线性膨胀。

## 决策 2：先登记、后下载

### 候选选项

- **选项 A（登记即下载）**：每登记一个成员就开始传输，闭合只负责收尾。
- **选项 B（闭合后统一下载）**：登记阶段只探测元数据，收到 `zipFinal` 后入队下载。

### 权衡与取舍

选项 A 能把枚举时间与传输时间重叠，但 Agent 中途放弃会留下无用的暂存数据，进度语义也会在「收集」与「下载」之间混杂。选项 B 让「收集中」是一个没有字节流动的清晰阶段，暂停、删除与放弃都不需要额外清理策略；代价是总耗时等于枚举加下载。

### 决策结论

采用选项 B。登记阶段只探测大小、真名、FinalURL 与续传信息；`collecting` 不占下载名额，也不被调度器启动。收到 `zipFinal` 或人工「立即打包」后进入 `queued`。

## 决策 3：连接预算沿用单任务设置

zip 任务在任务层只算一个任务，因此「全局并发任务上限」不需要改变。一个批次内部同时下载几个成员由引擎决定（最多 4 个），每个成员的分块连接数由任务的 `MaxConcurrency`（来自「单任务分块连接数」设置）在同时在飞的成员之间均分。小文件由下载器的 `MinChunkSize` 自然收敛到单连接。这样既不会让 100 个小文件各开几十条连接，也不会让用户设置对批次失效。

## 决策 4：暂存 + 打包，失败可分离重试

成员先落到由任务分片路径派生的暂存目录，文件名为扁平的 `m00001.part`；zip 内路径单独记录并校验。打包阶段按登记顺序写入 `<目标>.sheepget`，成功后原子改名，失败保留暂存。成员下载失败属于传输失败，重试只补失败或缺失成员；打包失败属于处理失败，「仅重试处理」直接复用暂存成员，不重新下载。打包前发现成员文件缺失时归为传输失败，让界面给出「重试下载」。

## 决策 5：批次边界由使用场景决定

批次不是按下载源或文件类型划分，而是按用户会一起使用的场景划分：

- 同一个模型/应用的文件即使分布在不同主机（HuggingFace、GitHub Release、厂商 CDN）也属于同一批次；
- 成员本身已经是 zip 时原样嵌套进外层 zip，不因为「要解压两次」而拆成第二个任务；
- 一个大的模型权重如果属于这个应用/模型，就属于批次；「单个大文件不聚合」只适用于没有任何同伴的独立下载；
- 用户要求「模型和它的依赖」「能跑起来的一整套」时，模型、运行时、依赖、示例与许可证都属于同一批次。

除非用户明确要求分开打包，否则不得为同一个应用/模型/场景创建第二个 zip 任务。`zipFinal` 不可撤销，且没有取消/删除 API，因此必须在闭合前枚举完所有依赖；闭合后发现遗漏时，应向用户说明并询问是否新建批次，而不是静默再建一个任务。

## 决策 6：API 与成员命名

`POST /api/v1/tasks` 增加 `zipId`、`zipName`、`zipPath`、`zipFinal`。不传 `zipId` 时行为完全不变。成员在 zip 内的路径必须保持原名：路径冲突直接 409，不自动改名——模型文件改名会直接破坏使用方。批次闭合、名称/目录不一致、成员路径冲突都返回 409；探测硬失败返回 400，探测超时按未知大小接收。

## 决策 7：重启与安全阀

`collecting` 在重启后保持收集，Agent 可以继续登记或补发闭合；`queued/downloading/processing` 在重启后落到 `paused`，由用户手动继续。Agent 忘记闭合时，桌面端提供「立即打包」，避免批次永远停在收集阶段。成员请求头随成员持久化，但绝不进入事件载荷或日志。
