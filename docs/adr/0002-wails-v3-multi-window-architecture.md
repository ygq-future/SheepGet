# 采用 Wails v3 Beta 架构支撑桌面多原生窗口与系统托盘

SheepGet 作为现代桌面下载管理器，其交互不仅包含主管理界面，还要求在应用驻留系统托盘时，能由浏览器扩展或剪贴板监听独立唤起小巧的文件信息窗口，并支持多任务共用的独立共享下载进度窗口。为实现真实的原生多窗口（Native Multi-Window）与系统托盘集成，决定将底层框架由 Wails v2 升级至 Wails v3 Beta。

## 决策背景

1. **多原生窗口诉求**：
   - 业务规格明确定义了主窗口、文件信息窗口和共享下载进度窗口各自独立的生命周期。当主窗口关闭常驻托盘时，外部下载触发不能粗暴弹出主窗口，而必须精准弹出独立的辅助窗口。
   - Wails v2 架构为单一窗口声明式设计，不支持在单进程内动态创建多个独立的原生 Webview 窗口；若要在 v2 实现多窗口，必须依赖侵入性的平台专属 hack 或额外辅助子进程，这会破坏统一跨平台抽象并引入高昂的 IPC 同步复杂度。
2. **官方原生支持**：
   - Wails v3 Beta（已演进至 `v3.0.0-beta.20`）提供了程序化架构（Procedural API），将窗口解耦为一等公民（`app.Window.NewWithOptions`），原生支持在同一个 Go 后端中动态创建、隐藏、销毁多个窗口，并原生提供跨平台系统托盘（`app.SystemTray.New()`）与解耦的 Service 体系。

## 核心架构原则

1. **单一后端实例与多窗口视图**：
   - Go 后端单实例运行，作为所有下载调度、状态存储和配置中心的唯一事实来源。
   - 主窗口、文件信息窗口、共享进度窗口共享同一个后端 Service 实例，窗口间通过后端 Event 总线与统一状态同步，杜绝前端多窗口之间的复杂私有通讯。
2. **窗口职责与生命周期**：
   - **主窗口（Main Window）**：常规大小，承载全量任务管理、主列表操作与配置入口；关闭时隐藏至托盘，不退出应用进程。
   - **文件信息窗口（File Info Window）**：小巧无边框/原生阴影辅助窗口，受控单例排队展示；确认或取消后隐藏或关闭，不联动显示主窗口。
   - **共享下载进度窗口（Shared Progress Window）**：浮动窗口，展示活跃任务实时分块与进度、置顶完成信息；根据配置自动弹出或由托盘/菜单手动调出。
3. **前端多窗口路由与构建**：
   - 前端 Vite 采用单页多路由或多入口视图模式，每个原生窗口加载时根据 URL 参数（如 `/?window=fileinfo` 或 `/?window=progress`）挂载对应的专门轻量组件树，避免加载无关的主界面重型 DOM。

## 权衡与风险缓解

- **Beta 阶段稳定性风险**：Wails v3 API 正处于稳定化最终打磨期。我们通过锁定特定 Beta 版本（`v3.0.0-beta.20`）、严格执行跨平台自动化门禁（Go 测试 + 前端构建）来阻断上游偶发破坏性变更。
- **构建脚本适配**：CLI 工具链由 `wails` 切换为 `wails3`，更新 `scripts/quality-gate.mjs` 与 CI 工作流以对接新的构建指令。
