# SheepGet 需求讨论

本文件记录需求输入及待澄清项；候选项尚未构成最终规格。

## 已明确的产品方向

- 桌面端目标平台为 Windows、macOS、Linux，技术栈暂定 Wails + Go + Web 前端；各平台交付顺序待讨论。
- 配套扩展支持 Chrome 和 Edge，随软件附带扩展文件，由用户通过浏览器开发者模式手动加载。软件提供安装引导；扩展更新后的重新加载流程待细化。
- UI 采用 Modern refined desktop utility UI，参考 Linear + Raycast 的克制、精致和高信息密度，各组件具有流畅的动画过渡。
- 浏览器资源发现以通用下载方式为范围。
- HLS 首期支持已有的点播资源下载，直播录制不在范围内。
- 媒体分片下载成功但合并处理失败时，保留已下载分片，任务显示“处理失败”及原因，并提供“重试处理”；重试仅重新执行合并处理。处理成功后清理临时分片，展示可打开的成品文件。
- 媒体分片下载结束即释放下载名额，排队下载可补位；合并处理期间显示处理状态，成品生成后展示完成信息与打开操作。
- 媒体存在多个清晰度时，点击悬浮条后先让用户选择清晰度，再进入文件信息对话框。清晰度在进入对话框时固定，对话框展示已选清晰度；手动确认下载和提前下载均使用该选择。
- 媒体悬浮条小巧精致，停靠在对应播放器右上角外侧（右边缘与播放器对齐、不遮挡画面）并随其移动；多个播放器分别拥有各自的悬浮条。播放器滚出视口时隐藏，滚回时恢复。
- 取消文件信息对话框后，媒体悬浮条仍保持显示。手动关闭仅隐藏当前播放器的悬浮条，直到页面刷新或重新打开；其他播放器不受影响。
- 无法关联到具体播放器的媒体资源，展示在浏览器工具栏的扩展弹窗中，作为当前页面的资源列表；能够关联播放器的资源才显示悬浮条。
- 默认打开文件信息对话框时等待用户确认才开始下载；可通过设置启用打开对话框即开始下载。
- 文件信息对话框展示文件名、类型、大小、来源与保存位置；HLS 另展示已选清晰度、可获得的时长和大小信息。字段获取能力及缺失时的行为待评估，交互参考 IDM。
- “显示文件信息时立即下载”控制对话框打开期间的后台下载。开启后仍显示对话框，用户可修改文件名、保存路径；后台下载可在确认前完成，此时确认后按共享下载进度窗口的规则展示完成信息。
- 尚未确认且没有实际下载时，取消文件信息对话框不保留任务。
- 提前下载后取消文件信息对话框：停止传输，保留任务在下载列表中，状态为暂停。
- 用户手动确认下载后，任务保存在下载列表中；即使尚未收到数据就连接失败，也保留失败任务以供查看和重试。

## 用户提供的候选功能

- 开机启动开关。
- 关闭主窗口后固定驻留系统托盘，继续下载、浏览器接管和已开启的剪贴板监视；不提供“关闭主窗口即退出”设置。
- 监视剪贴板并自动开启下载的开关。
- 剪贴板监视复用自动接管文件类型配置：HTTP/HTTPS 链接按 URL 路径后缀匹配，忽略查询参数；命中时打开文件信息对话框，按既定提前下载设置处理。普通网页地址及无明确后缀的链接通过手动添加处理。
- 自定义暂时停止接管、强制接管下载的快捷键采用按住临时生效、松开恢复的方式，不改变全局接管设置。暂停接管时本次交给浏览器；强制接管时本次忽略文件类型和站点排除规则，交给 SheepGet 并按文件信息对话框流程处理。可用按键组合及浏览器捕获限制待核实。
- 代理模式：不使用代理、系统代理、自定义代理地址。
- 代理设置作用于 SheepGet 自身联网；系统代理模式读取系统配置。切换设置后，正在下载的任务继续使用原配置，新任务及暂停后继续的任务使用最新配置。
- 按文件类型自动开始下载，预置常用类型；配置不自动开始下载的站点。
- 分类只决定保存目录，自动接管使用独立的文件类型配置。
- 首期下载入口为 Chrome / Edge 扩展接管、剪贴板监听及手动添加链接；其他桌面应用通过复制链接交给 SheepGet，其自身下载不纳入拦截范围。
- 站点排除按发起下载的页面域名匹配，包含其子域名；仅影响自动接管，用户主动点击媒体悬浮条或手动添加链接仍可下载。
- 分类保存：预置文件、视频、音频、图片、压缩包、软件；支持自定义分类，每类可配置保存目录和后缀规则。文件信息对话框中手动选择的保存位置优先；未匹配的归入文件。
- 自定义分类优先于内置分类匹配，后缀规则允许重叠。例如自定义分类包含 rar 时，rar 优先归入该分类，内置压缩包分类仍保留 rar 规则。自定义分类支持拖动排序，新增分类默认置顶；从上往下匹配，采用第一个命中的分类，全部未命中再匹配内置分类。
- 临时文件夹设置。
- 使用服务器提供的文件创建时间；时间字段含义与可用性待核实。
- 提供“显示下载进度窗口”和“保留下载完成信息”两个独立开关。
- 下载进度采用一个独立于主界面的共享窗口。文件信息对话框确认下载后，在开启显示下载对话框时展示该窗口；后续任务追加到同一窗口。
- 下载中的任务区域显示实时线程下载区块和下载进度，并按下载进度从高到低实时排序。已完成任务固定在顶部，不参与下载中任务的实时重排；打开文件、打开文件夹操作仅在完成后显示。窗口具有高度上限，超出部分在窗口内滚动。
- 任务完成后，原任务区域替换为完成信息，提供打开文件、打开文件夹及手动关闭该区域的操作。
- 设置支持控制打开文件或打开文件夹后是否自动移除该任务的完成信息。
- 开启“保留下载完成信息”时，完成后任务区域转为完成信息；关闭时，完成后从进度窗口移除，主界面的下载记录保留。关闭进度窗口自动显示时，任务完成也不主动弹出窗口。
- 显示文件信息时立即开始下载的开关，默认等待用户确认。
- 重复链接与目标位置同名文件冲突分别处理。重复链接初期按完整 URL 相同判定，默认询问，提供继续任务、重新下载、另存副本等处理方式；继续已有任务直接回到原任务，创建新下载时再检查目标位置冲突。
- 目标位置已有同名文件时默认询问，可选择覆盖或自动添加序号。
- 连接数量设有全局默认值，每个任务可单独选择覆盖；采用固定并发上限及动态分块分配。空闲下载通道领取下一块，实际活跃数量受文件大小、剩余块及服务器能力限制。
- 同时下载任务数量默认上限为 3，可在设置中修改；超出的任务按添加顺序排队，任务完成或暂停后自动补位。“显示文件信息时立即下载”也遵守任务数量上限，对话框打开期间可处于等待状态。
- 软件重新启动后保留未完成任务，恢复下载必须由用户手动选择任务并点击继续。

## 当前讨论焦点

本轮产品需求访谈已完成。已确认行为作为后续整理规格的依据；技术验证若发现能力限制或规则冲突，再针对具体影响讨论。常规行为直接按既有需求细化。

## 下载交接与恢复（已确认）

- 浏览器扩展确认 SheepGet 已接收任务后，才结束浏览器侧下载；软件未运行时尝试唤起，无法连接时保留浏览器下载并提示。具体交接与唤起机制需验证。
- 支持更新过期下载链接，也可从浏览器重新获取所需下载信息。验证仍为同一文件后续传；无法确认一致性时提示重新下载，避免错误拼接。
- 手动添加 m3u8 后解析清单，存在多个清晰度时先选择，再进入文件信息对话框；进入对话框后清晰度固定，与悬浮条入口顺序一致。
- 信息获取不完整时仍允许下载：大小显示“未知”，文件名允许用户修改。默认只执行获取信息所需的请求，不持续下载正文；HLS 可以读取清单，但不提前下载媒体分片。正式传输须由用户确认或提前下载设置触发。

## 技术验证与后续规格整理

- 验证 Chrome / Edge 三平台的下载交接、桌面程序唤起和快捷键捕获边界，以及侧载扩展更新流程。
- 核实服务器时间字段含义及各平台文件时间支持，避免将修改时间当成创建时间。
- 验证媒体库对目标 TS/fMP4、H.264/H.265 + AAC 组合的兼容性，形成支持矩阵。
- 验证文件身份与续传一致性判断、元信息探测请求的边界。
- 用测试确定慢区块阈值；媒体处理并发数量及其他常规运行参数在技术设计中细化。
- 整理规格时集中检查任务状态、进度窗口排序与各开关的交互，发现影响已确认行为的冲突时再提出。

## 媒体处理方向（正式确定）

默认 Pure Go、轻量优先，优先覆盖常见 HLS / m3u8、MPEG-TS、fMP4 及 H.264 / H.265 + AAC 组合。通过 Go 原生实现或成熟 Go 媒体库进行正确组装、demux、mux 与无损 remux；不提供重新编码，暂未支持的 codec、封装或复杂媒体结构明确提示“不支持”。这些是目标支持范围，具体库及组合能力需验证。

统一处理链路为 HLS Engine → Media Processor → Output。HLS Engine 管理 playlist、segment、加密、下载和媒体信息组织；Media Processor 负责 TS/fMP4 解析、音视频轨合并和 MP4 输出，具体库封装于后端内部。

第一版默认 Native Go Backend，FFmpeg 不是必需依赖，程序不默认打包完整 FFmpeg runtime。未来可通过可替换后端接入 FFmpeg Backend，支持用户指定程序、可选组件安装或其他动态接入方式，保持 HLS Engine 与任务系统的处理边界稳定。未来后端接入不是首期实现要求。

详见 [ADR-0001](adr/0001-native-go-media-processing.md)。

## 连接数量评估（已确认）

采用每任务固定并发上限及动态分块分配：空闲下载通道领取下一块，实际活跃数量受文件大小、剩余块及服务器能力限制。全局默认可由单任务覆盖。

首期范围为配置上限内的并发下载与区块调度。工程判断：依据吞吐自适应寻找最佳并发数还需要速度采样、试探增减、防震荡以及区分网络波动、服务器限流和多个任务争用；目前尚无项目实测数据证明收益，稳定性验证面明显更大。

依据：

- [aria2 官方手册](https://aria2.github.io/manual/en/html/aria2c.html#cmdoption-s) 将拆分数量与服务器连接上限、最小拆分大小分别控制。
- [RFC 9110 Range](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2) 允许服务器忽略 Range，需验证实际响应并支持单路回退。
- [RFC 9110 部分响应合并](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7.3) 要求处理资源版本一致性。

上述建议是基于协议要求的工程评估，尚未进行下载性能实测。

## 慢区块处理（已确认纳入首期）

在固定并发上限内支持有条件的慢区块剩余区间再拆分。优先正常待下载块，仅在存在空闲下载通道且无普通待领取块时处理拖尾区块。

检测结合持续采样、同任务其他通道的近期速度、剩余数据量与预计耗时；1 MB 超过 10 秒仅作为问题示例。整体变慢或缺少可靠比较样本时保守处理，不凭绝对低速反复拆分。设置最小拆分大小、冷却时间及拆分次数限制；没有收益时停止继续拆分。完全停滞走超时与重试流程。

拆分只处理尚未完成的数据，保留已下载部分，保证每段数据只有一个写入者并校验资源一致性。HTTP Range 没有通用的在途修改响应区间机制，需由客户端安全终止旧请求并重新分配剩余区间等方式实现；复杂度高于普通区块队列，但范围可控。

依据：[RFC 9110 Range](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)、[Go 请求取消](https://pkg.go.dev/net/http#NewRequestWithContext)。具体阈值通过测试确定，不能保证拆分必然提速。
